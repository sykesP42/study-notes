# C++ 堆、栈与内存管理

> C++ 中对象的内存分配机制，包括**栈（Stack）** 与**堆（Heap）** 的区别、各种对象的生命周期、`new`/`delete` 的内部运作机制，以及动态分配内存的底层布局细节。理解这些内容是写出健壮、无内存泄漏的 C++ 程序的必备基础。

## 一、栈和堆

### 1.1 基本概念

在 C++ 中，对象可以存放在两种不同的内存区域：

|区域|特点|管理方式|
|---|---|---|
|**栈（Stack）**|存在于某个作用域（scope）内的内存空间。函数被调用时，会形成一个栈帧，用于存放参数、返回地址以及函数内声明的局部变量|**自动管理**|
|**堆（Heap）**|由操作系统提供的全局内存空间，程序可以通过 `new` 关键字动态分配内存块|**手动管理**|

**示例代码**：


```cpp

{
    Complex c1(1, 2);         // c1 来自栈 —— 局部对象
    Complex* p = new Complex(3); // *p 来自堆 —— 动态分配的对象
    // ...
}   // c1 在此处自动销毁，但 *p 仍然存在（如果不 delete，就会内存泄漏！）
```

**关键区别**：

- **栈对象**：作用域结束时**自动释放**，析构函数自动调用
    
- **堆对象**：必须由程序员**手动释放**（使用 `delete`），否则会造成**内存泄漏**
    

### 1.2 各种对象的生命周期

> 📖 **参考**：cppreference 存储期 —— “存储期是对象的属性，它定义了包含该对象的存储的最小潜在生存期。存储期由用于创建对象的构造决定。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/storage_duration&diff=174934&oldid=174927)“自动存储期 —— 变量在封闭代码块开始时分配，在结束时释放。静态存储期 —— 变量在程序开始时分配，在程序结束时释放。”

#### ① 栈对象（Stack Object / Automatic Object）

```cpp

void func() {
    Complex c1(1, 2);   // 栈对象（自动存储期）
    // ...
}   // 离开作用域，c1 的析构函数自动被调用
```

**定义**：在作用域内直接声明的对象，具有**自动存储期（automatic storage duration）** 。

**生命期**：在作用域结束时结束。当程序执行离开该作用域（例如函数返回或代码块结束），栈对象会自动被清理，其析构函数自动调用。

**核心特性**：自动管理，无需程序员干预。

#### ② 静态局部对象（Static Local Object）

```cpp

void func() {
    static Complex c1(1, 2);   // 静态局部对象
    // ...
}   // 离开作用域，析构函数不会被调用
```

**定义**：在作用域内使用 `static` 关键字声明的对象，具有**静态存储期（static storage duration）** 。

**生命期**：在作用域结束之后**仍然存在**，直到**整个程序结束**才销毁。离开作用域时，析构函数**不会被调用**；析构函数会在程序结束时被调用。

**使用场景**：当需要对象在函数调用之间保持状态时，可以使用静态局部对象。

#### ③ 全局对象（Global Object）

```cpp

Complex c1(1, 2);   // 全局对象（在任何函数之外）
int main() {
    // ...
}
```

**定义**：在任何函数或作用域之外声明的对象，具有**静态存储期**。

**生命期**：在整个程序结束之后才结束。它在程序开始运行之前（`main` 函数执行前）就已经存在，其构造函数在 `main` 之前被调用。程序结束时，其析构函数被调用。

**与静态对象的关系**：全局对象可以视为一种作用域为“整个程序”的静态对象。

#### ④ 堆对象（Heap Object）

```cpp

Complex* p = new Complex(1, 2);   // 堆对象（动态存储期）
// ...
delete p;   // 手动释放，触发析构函数
```

**定义**：通过 `new` 表达式在堆上动态分配的对象，具有**动态存储期（dynamic storage duration）** [](https://en.cppreference.com/mwiki/index.php?title=cpp/language/storage_duration&diff=174934&oldid=174927)。

**生命期**：在它被 `delete` 时结束。`delete` 操作会调用对象的析构函数，并释放其占用的内存[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)。

**正确用法**：`new` 和 `delete` **必须成对出现**。

```cpp

Complex* p = new Complex(1, 2);
// ... 使用 p ...
delete p;   // 必须记得释放
```
**内存泄漏（Memory Leak）**：这是使用堆对象时最需要警惕的错误。

- **产生原因**：只 `new` 了对象，却忘记 `delete`。
    
- **后果**：当作用域结束时，指针 `p` 的生命结束（指针本身被销毁），但指针所指向的堆对象**仍然存在**。由于指针已消失，程序再也无法访问或释放这块内存，导致内存泄漏[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)。
    

> 📖 **参考**：cppreference —— “为避免内存泄漏，返回的指针必须用 `std::free()` 或 `std::realloc()` 解除分配。”[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)

### 1.3 四种对象生命周期对比

|对比项|栈对象|堆对象|静态局部对象|全局对象|
|---|---|---|---|---|
|存储期|自动存储期|动态存储期|静态存储期|静态存储期|
|生命周期|离开作用域即结束|手动 `delete` 前一直存在|程序结束时结束|程序结束时结束|
|析构函数调用|自动调用|需手动 `delete` 触发|程序结束时自动调用|程序结束时自动调用|
|典型写法|`Complex c1(1,2);`|`Complex* p = new Complex(1,2);`|`static Complex c3(1,2);`|`Complex c4(1,2);`（全局作用域）|

## 二、`new` 操作深度剖析

### 2.1 `new` 表达式的内部机制

`new` 表达式（new expression）在底层执行两个核心步骤：分配内存和在分配的内存中构造对象[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/new&oldid=36500)。

> 📖 **参考**：cppreference —— “`new` 表达式分配一块内存区域，在其中初始化单个对象或对象数组，并返回指向第一个已构造对象的指针。内存由分配函数分配，即 `operator new` 或 `operator new[]`。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/new&oldid=36500)

当我们写下 `new Complex(1, 2)` 时，编译器将其转化为三个内部步骤：

```cpp

// 程序员写的代码
Complex* pc = new Complex(1, 2);
// 编译器将其转化为：
// 第一步：分配内存
void* mem = operator new(sizeof(Complex));   // 内部调用 malloc(n)
// 第二步：类型转换（将 void* 转换为 Complex*）
Complex* pc = static_cast<Complex*>(mem);
// 第三步：调用构造函数
pc->Complex::Complex(1, 2);   // 通过指针调用构造函数
```

**详细说明**：

|步骤|操作|说明|
|---|---|---|
|**① 分配内存**|调用 `operator new` 函数|`operator new` 是 C++ 提供的特殊分配函数，其内部实际调用的是 C 语言的 `std::malloc` 函数[](https://en.cppreference.com/mwiki/index.php?title=cpp/memory/new/operator_new&oldid=12561)。分配的内存大小由编译器根据 `sizeof(Complex)` 自动计算|
|**② 类型转换**|将 `void*` 指针转换为目标类型的指针|`operator new` 返回的是 `void*` 指针[](https://en.cppreference.com/mwiki/index.php?title=cpp/memory/new/operator_new&oldid=12561)，需要转换为 `Complex*`|
|**③ 调用构造函数**|通过转型后的指针调用构造函数|构造函数是成员函数，调用时会隐式传入 `this` 指针，指向当前分配的内存起始位置（即 `pc`）|

**构造函数与内存分配的关联**：  
构造函数通过 `this` 指针（即 `pc`）访问到分配的内存块，并将实部和虚部设置为传入的值。这样，内存分配和对象初始化就完成了结合。

> 📖 **参考**：cppreference —— “这些分配函数由 `new` 表达式调用，以分配内存，然后在该内存中初始化新对象。”“由于无法以其他方式显式调用构造函数，该表达式是动态构造对象的唯一方式。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/new&oldid=36500)

### 2.2 `delete` 表达式的内部机制

`delete` 表达式的操作与 `new` 表达式**完全相反**：先调用析构函数，再释放内存[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)。

```cpp

// 程序员写的代码
delete pc;
// 编译器将其转化为：
// 第一步：调用析构函数
pc->~Complex();
// 第二步：释放内存
operator delete(pc);   // 内部调用 free(pc)
```

> 📖 **参考**：cppreference —— “`delete` 表达式销毁先前由 `new` 表达式分配的对象，并释放获得的内存区域。内存由解分配函数释放，即 `operator delete` 或 `operator delete[]`。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)

**析构函数在 `delete` 中的作用**[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)：

- 析构函数负责清理对象内部动态分配的资源。
    
- 对于 `Complex` 类（没有动态分配内存），编译器提供的默认析构函数不做任何操作。
    
- 对于 `String` 类，析构函数需要释放内部动态分配的字符数组（`delete[] m_data`）。
    

**释放内存**：调用 `operator delete` 函数，内部实际调用 C 语言的 `std::free` 函数[](https://cppreference.dev/w/cpp/memory/c/free)。这一步骤释放的是**对象本身所占用的内存**（例如 `String` 对象本身只是一个指针，占用 4 或 8 字节）。

**关键区别**：

- `delete` 操作本身只负责释放**对象本身的内存**
    
- 对象内部动态分配的内存需要由**析构函数**负责释放
    

例如，`String` 对象被 `delete` 时：

1. 析构函数先释放内部的字符数组（`delete[] m_data`）
    
2. 然后 `operator delete` 再释放 `String` 对象本身
    

### 2.3 `new`/`delete` 对比总结

|对比项|`new` 表达式|`delete` 表达式|
|---|---|---|
|本质|先分配内存，再调用构造函数|先调用析构函数，再释放内存[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|
|底层调用|`operator new` → `std::malloc`[](https://en.cppreference.com/mwiki/index.php?title=cpp/memory/new/operator_new&oldid=12561)|`operator delete` → `std::free`[](https://cppreference.dev/w/cpp/memory/c/free)|
|执行顺序|分配内存 → 构造对象|析构对象 → 释放内存|

### 3.1 内存块的实际大小

使用 `std::malloc` 或 `new` 分配的内存，实际大小会**大于对象本身的大小**[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)。

**内存块的组成**（以 VC 调试模式为例）：

|组成部分|大小|作用|
|---|---|---|
|**调试头（Debug Header）**|32 字节|存放调试信息，用于内存泄漏检测|
|**Cookie（上下各一个）**|上下各 4 字节，共 8 字节|记录整块内存的大小，供 `std::free()` 回收时使用|
|**对象数据**|取决于类|对象本身的数据|
|**调试尾（Debug Tail）**|4 字节|用于内存越界检测|
|**填充（Pad）**|不定|对齐到特定边界（VC 下为 16 的倍数）|

> 📖 **参考**：cppreference `std::malloc` —— “如果分配成功，返回指向所分配内存块中最低字节的指针，该指针已适当对齐以适用于任何标量类型。”[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)“`std::free` 解分配先前由 `std::malloc` 分配的空间。”[](https://cppreference.dev/w/cpp/memory/c/free)

### 3.2 Cookie 的作用与标记技巧

**Cookie 的作用**：记录整块内存的大小，供系统回收时使用。`std::free()` 函数仅凭指针就能知道要释放多大内存，正是依靠 Cookie 中的长度信息[](https://cppreference.dev/w/cpp/memory/c/free)。

**一个精妙的标记技巧**：由于内存块大小通常是 16 的倍数，其 16 进制表示的最后 4 个 bit 都是 0。因此，借用最后一个 bit 来标记内存状态：

- **1**：表示已分配（给程序使用）
    
- **0**：表示已回收（还给系统）
    

例如，64 字节的内存块：

- 64 的 16 进制是 `0x40`
    
- 已分配时记录为 `0x41`（最低位设为 1）
    
- 已回收时记录为 `0x40`（最低位为 0）
    

### 3.3 调试模式 vs 发布模式下的内存计算

#### 单个对象的内存计算

**Complex 对象（8 字节，两个 `double`）**：

|组成部分|调试模式（Debug）|发布模式（Release）|
|---|---|---|
|对象本身|8 字节|8 字节|
|调试头|32 字节|❌ 无|
|调试尾|4 字节|❌ 无|
|Cookie（上下）|8 字节|8 字节|
|小计|52 字节|16 字节|
|对齐到 16 倍数|64 字节（0x40）|16 字节（0x10）|
|Cookie 标记|0x41|0x11|

**String 对象（4 字节，仅一个指针，32 位系统）**：
![[Pasted image 20260909102723.png]]

| 组成部分       | 调试模式（Debug） | 发布模式（Release） |
| ---------- | ----------- | ------------- |
| 对象本身       | 4 字节        | 4 字节          |
| 调试头        | 32 字节       | ❌ 无           |
| 调试尾        | 4 字节        | ❌ 无           |
| Cookie（上下） | 8 字节        | 8 字节          |
| 小计         | 48 字节       | 12 字节         |
| 对齐到 16 倍数  | 48 字节（0x30） | 16 字节（0x10）   |
| Cookie 标记  | 0x31        | 0x11          |

**关键结论**：

- 发布模式下，调试头和调试尾被移除，内存占用大幅减少
    
- 无论是否调试模式，Cookie 始终存在，用于内存回收
    
- 内存块大小必须对齐到 16 的倍数（在不同编译器或平台上可能不同）
    

### 3.4 动态分配数组（Array `new` / `delete`）

#### 数组内存布局
![[Pasted image 20260909102723.png]]
使用数组形式的 `new` 表达式（`new[]`）分配数组时，内存块中会额外多出一个**计数器（Counter）** ：

| 组成部分         | 大小              | 作用        |
| ------------ | --------------- | --------- |
| Cookie（上下）   | 各 4 字节          | 记录整块内存大小  |
| 计数器（Counter） | 4 字节            | 记录数组元素个数  |
| 对象数据         | `n × sizeof(T)` | n 个对象依次排列 |
| 调试头/尾        | 调试模式才有          | 调试信息      |

**计数器的作用**：记录数组中元素的个数（例如 `new Complex[3]` 会记录一个整数 3），供 `delete[]` 读取，以便知道需要调用多少次析构函数[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)。

#### 内存计算示例

**Complex 数组（3 个对象，每个 8 字节）—— 调试模式**：

|组成部分|计算|大小|
|---|---|---|
|对象数据|3 × 8|24 字节|
|调试头|-|32 字节|
|计数器|-|4 字节|
|Cookie（上下）|-|8 字节|
|小计|24 + 32 + 4 + 8|68 字节|
|对齐到 16 倍数|68 → 80|80 字节（0x50）|
|Cookie 标记|80 → 0x50，已分配|0x51|

**String 数组（3 个对象，每个 4 字节，32 位）—— 调试模式**：

|组成部分|计算|大小|
|---|---|---|
|对象数据|3 × 4|12 字节|
|调试头|-|32 字节|
|计数器|-|4 字节|
|Cookie（上下）|-|8 字节|
|小计|12 + 32 + 4 + 8|56 字节|
|对齐到 16 倍数|56 → 64|64 字节（0x40）|
|Cookie 标记|64 → 0x40，已分配|0x41|

### 3.5 Array `new` 必须搭配 Array `delete`

这是 C++ 内存管理中最常见的误区之一。

#### 正确用法 vs 错误用法

```cpp

String* p = new String[3];   // array new，分配了 3 个 String 对象
// ...
delete[] p;   // ✅ 正确：array delete，调用 3 次析构函数
// delete p;  // ❌ 错误：只调用 1 次析构函数
```

> 📖 **参考**：cppreference —— “`delete` 表达式销毁先前由 `new` 表达式分配的对象。第一种形式销毁单个非数组对象，第二种形式销毁由 `new[]` 表达式创建的数组。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)

#### 错误用法的后果

**普遍误解**：很多人认为 `delete p`（缺少方括号）会导致整个数组内存块泄漏。

**事实**：

- **不会泄漏的部分**：整个数组内存块（包括 Cookie）会被**正确回收**，因为 `std::free()` 依赖 Cookie 记录的大小，不需要知道是数组还是单个对象[](https://cppreference.dev/w/cpp/memory/c/free)。
    
- **真正泄漏的部分**：未被调用析构函数的第 2、3 个 `String` 对象内部动态分配的 `char*` 内存**无法被释放**，导致内存泄漏。
    

#### 不同类别的差异

**对于 `Complex` 类（无内部动态内存）**：

- 即使错误使用 `delete`（缺少方括号），也不会造成内存泄漏
    
- 原因：析构函数没有释放内存的操作，调用一次或多次结果相同
    
- 但仍是不规范的行为，可能导致未定义行为[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)
    

**对于 `String` 类（有内部动态内存）**：

- 错误使用 `delete` 会造成**严重内存泄漏**
    
- 原因：只有第一个对象的析构函数被调用，其余对象的内部内存永远无法释放
    

**最佳实践**：**无论类内部是否有动态内存，只要使用 `array new`，就必须使用 `array delete`**，养成良好习惯，避免潜在风险。

> 📖 **参考**：cppreference —— “对于数组形式，表达式必须是空指针值或先前由数组形式的 `new` 表达式获得的指针值。如果表达式不是空指针，则 `delete` 表达式会调用被销毁对象的析构函数，或数组的每个元素的析构函数（从最后一个元素到第一个元素）。”[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)

#### 正确用法对比

|对比项|`delete p`（单个对象）|`delete[] p`（数组）|
|---|---|---|
|析构函数调用次数|1 次[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|数组元素个数次[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|
|适用场景|单个对象[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|数组对象[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|

## 四、知识小结

### 4.1 核心概念速查表

|知识点|核心内容|关键要点|
|---|---|---|
|**对象内存来源**|对象可来自栈或堆|栈对象自动销毁，堆对象需手动 `delete`|
|**静态对象与全局对象**|静态对象在作用域结束后仍存在；全局对象在 `main` 前存在|两者都在程序结束时销毁|
|**`new` 的分解动作**|①调用 `operator new`（实际调用 `malloc`）②类型转换③调用构造函数[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/new&oldid=36500)|三个步骤顺序不可颠倒|
|**`delete` 的分解动作**|①调用析构函数②调用 `operator delete`（实际调用 `free`）[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|先析构后释放内存，顺序与 `new` 相反|
|**内存分配细节**|调试模式下：Cookie + 调试头尾 + 填充；非调试模式仅含 Cookie|内存块大小需对齐[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)|
|**Array `new` 与 Array `delete`**|`new[]` 必须搭配 `delete[]`[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|否则只调用一次析构函数，导致内部动态内存泄漏[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)|

### 4.2 内存布局图（调试模式）

```text

┌─────────────────────────────┐ ← 内存块起始
│   Cookie（上）- 4 字节        │ ← 记录总大小，标记已分配/回收
├─────────────────────────────┤
│   Debug Header - 32 字节      │ ← 调试信息
├─────────────────────────────┤
│   [对于数组] Counter - 4 字节 │ ← 记录元素个数（仅 array new）
├─────────────────────────────┤
│   对象数据                    │ ← 实际对象（可能多个，数组排列）
│   (如 Complex: 8 字节)        │
├─────────────────────────────┤
│   Debug Tail - 4 字节         │ ← 内存越界检测
├─────────────────────────────┤
│   Pad（填充）- 不定          │ ← 对齐到 16 的倍数
├─────────────────────────────┤
│   Cookie（下）- 4 字节        │ ← 与上 Cookie 相同
└─────────────────────────────┘
```
### 4.3 关键要点总结

1. **栈对象自动管理**：离开作用域自动析构，无需程序员干预
    
2. **堆对象手动管理**：`new` 和 `delete` 必须成对出现，否则内存泄漏[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)
    
3. **静态/全局对象**：程序结束时才销毁，`main` 执行前已构造
    
4. **`new` 的三步走**：分配内存（`malloc`）→ 类型转换 → 构造[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/new&oldid=36500)
    
5. **`delete` 的两步走**：析构 → 释放内存（`free`）[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)
    
6. **Cookie 记录大小**：`std::free()` 凭 Cookie 知道要释放多大内存[](https://cppreference.dev/w/cpp/memory/c/free)
    
7. **Cookie 的标记技巧**：借用最低位标记分配/回收状态
    
8. **`array new` 必须配 `array delete`**：否则数组元素的析构函数无法全部调用[](https://en.cppreference.com/mwiki/index.php?title=cpp/language/delete&oldid=69671)
    
9. **内存泄漏的本质**：不是整块内存无法回收，而是对象内部资源未被释放[](http://sq.cppreference.com/w/cpp/memory/c/malloc.html)
    
10. **对齐要求**：内存块大小通常需对齐
